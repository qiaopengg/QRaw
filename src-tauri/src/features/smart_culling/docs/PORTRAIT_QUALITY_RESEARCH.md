# 人像清晰度、光学与构图：调研与接入结论

- 核查日期：2026-09-08
- 状态：AI 弃选区与旧人像打星路径清理已实现；eDifFIQA(T) 与新质量观测已落地并通过工程验证，自动清晰度门禁与光学/构图通过线尚未校准
- 唯一评分标准：[PORTRAIT_RATING_STANDARD.md](./PORTRAIT_RATING_STANDARD.md)
- 本文给出工程建议，不新增分值、自动弃选阈值或发布验收口径。

## 1. 当前生效的打星入口与问题证据

下表描述仍在生效的判定规则。第 7 节的新观测不改动这些阈值，不能把“已有模型数据”解释成“已经完成清晰度分类验收”。

| 项目 | 当前实现 | 结论 |
| --- | --- | --- |
| 人脸定位 | 现有 YuNet 检测人脸，`analysis.rs` 裁剪人脸区域 | “先找到人脸再评估”已完成第一步，可继续复用 |
| 清晰度 | 人脸裁剪的拉普拉斯方差；`mode_evidence.rs::person_gate_clarity_evidence` 用固定阈值输出三态 | 尚不能认定为稳定可靠的人像清晰度方案 |
| 不清晰条件 | 整图锐度小于 2.4 且最弱目标脸锐度小于 2.8 | 判断仍受背景影响，清晰背景可能让模糊的人脸只能进入无法确定 |
| 清晰条件 | 最弱目标脸检测分数至少 0.78，且归一化锐度至少 0.55（原始值约 83） | 检测分数不能替代清晰度；两侧阈值之间有很大的无法确定区间 |
| 光学 | 灰度直方图统计接近纯黑、纯白的像素；通用质量代理混合锐度与曝光 | 尚未完整判断曝光、色彩、噪声等质量 |
| 构图 | 通用构图证据明确标为不可用 | 尚无经过验证的构图通过条件 |
| 人像联合加星 | `portrait_rating_adapter.rs` 将光学、构图均标为无法确定 | 当前该项为 +0，人像实际上限为 4 星；这是未完成的接入，不是已经具备能力后漏加分 |

当前清晰度无法确定会产生 `requires_human_review = true`。数据中的数字 0 在此时只是占位，不能按有效 0 星弃选。这轮新增的分区以复核状态优先判断，解决其与有效 0 星混在一起的问题；没有通过放松清晰度阈值掩盖无法确定。

## 2. 人脸清晰度：采用组合评估

用户提出的方向可行。建议复用现有人脸检测，增加对齐、局部细节与质量模型的组合评估。人脸质量模型通常也受姿态、光照影响，不能将其总分直接解释成失焦程度。NIST 的质量评估也明确区分综合分与聚焦、照明、噪声等质量分量，并以预测识别失败作为一类评测目标。[NIST FATE Quality](https://pages.nist.gov/frvt/html/frvt_quality.html)

### 候选与选择

| 方案 | 官方依据及采用建议 | 适用边界 |
| --- | --- | --- |
| YuNet + eDifFIQA(T) | [OpenCV Zoo 官方实现](https://github.com/opencv/opencv_zoo/tree/main/models/face_image_quality_assessment_ediffiqa)已提供检测、对齐、轻量人脸质量评估组合；优先做本项目候选 | 质量分不等于纯模糊分；目录标明 CC-BY-4.0，实际接入须固定模型版本、哈希和署名 |
| OFIQ | [BSI 官方项目](https://github.com/BSI-OFIQ/OFIQ-Project)是 ISO/IEC 29794-5 参考实现，适合作为离线对照 | C/C++ 集成及依赖较重；其[锐度说明](https://github.com/BSI-OFIQ/OFIQ-Project/blob/main/OFIQlib/modules/measures/Sharpness.h)明确用于同一人物多张照片的相对比较，不宜单独判断单张绝对清晰度 |
| 局部梯度、边缘与高频细节 | 工程建议：保留现有拉普拉斯指标，补充梯度强度、边缘扩散等候选特征 | 多个锐度算子高度相关，不得将简单投票当成独立验证；阈值需要实际照片校准 |

检索时 [OpenCV Zoo](https://github.com/opencv/opencv_zoo)约 1.0k 星，OFIQ 125 星。前者是模型集合的星数，后者的标准依据更强；星数不能证明某个模型在 QRaw 上准确。本次没有找到同时满足“高星、权威、即插即用、可直接判定摄影人脸绝对清晰度”的单一工具。

### 推荐处理顺序

1. 使用现有 YuNet 和主人物选择逻辑，确定真正需要评价的人脸；不把背景中的小人脸作为主人物。
2. 记录原始人脸像素尺寸、姿态、遮挡和裁剪有效性。检测失败或输入不足时给出具体无法确定原因。
3. 将人脸对齐，并限制在面部有效区域内分析。保留原始尺度信息，同时比较受控尺度的细节；不能只把人脸缩得很小后判断清晰度。
4. 用局部细节特征评估失焦/运动模糊，用 eDifFIQA(T) 提供辅助质量证据。噪点、过度锐化、美颜和压缩均作为需要检验的干扰因素。
5. 同一人物的连拍可加入相对清晰度排序；“这一组里最清楚”仍不能自动等于“绝对清晰”。
6. 综合证据映射为清晰、不清晰、无法确定。只有经过校准的明确不清晰结论触发 0 星；证据冲突继续进入待人工复核。

这是待验证的组合方案，不能承诺接入模型后立即消除无法确定。实施时先记录新指标并与现有结果对照，再用冻结阈值替换当前清晰度适配器；最终只能保留一个生效的清晰度决策入口。

## 3. 曝光、色彩与构图

光学质量建议评估整图及主体脸的高光/暗部裁切、局部对比度、通道溢出、噪声与压缩。色彩偏差需要考虑拍摄光源和创作风格，不能把暖色调、低调照片或有意剪影直接判为错误。用于分析的预览、色彩空间、RAW 解码及缩放方式应固定，否则同一原图也会得到不同数值。

| 方案 | 可以提供什么 | QRaw 中的定位 |
| --- | --- | --- |
| [OpenCV BRISQUE](https://docs.opencv.org/4.x/d8/d99/classcv_1_1quality_1_1QualityBRISQUE.html) | 无参考图像质量分，官方有训练模型 | 通用技术质量对照；不能分别解释曝光是否合适、肤色是否准确或构图是否通过 |
| [Google MUSIQ](https://github.com/google-research/google-research/tree/master/musiq) | 多尺度图像质量模型；官方报告覆盖技术质量及审美数据集 | 更强的整体质量候选，须分别选择技术/审美权重，验证推理耗时与移植成本；[官方研究说明](https://research.google/blog/musiq-assessing-image-aesthetic-and-technical-quality-with-multi-scale-transformers/) |
| [SAMP-Net / CADB](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB) | BMVC 2021 构图质量研究；数据提供三分法、黄金比例、居中、对称、消失点等 13 类构图标注 | 最贴近本次构图需求的研究候选，约 174 星；数据含构图类别不代表模型能直接解释每个类别或生成通过判定 |

构图建议结合主人物位置、显著区域、地平线/线条与构图模型。三分法、居中、对称等是可选择的构图方式，不要求一张照片同时满足；单纯检测人物靠近网格交点不足以证明构图优秀。先确定画面适用的构图方式，再校准整体是否达到基本通过线。

[IQA-PyTorch 当前许可证](https://github.com/chaofengc/IQA-PyTorch/blob/main/LICENSE)为 PolyForm Noncommercial，不能默认按通用商用依赖引入；各模型权重仍需分别核查。[idealo NIMA](https://github.com/idealo/image-quality-assessment)已归档，适合作为历史对照，不作为本轮优先集成对象。代码许可证不自动等于模型权重和训练图片的使用授权。

光学与构图各自输出通过、未通过、无法确定，再由现有唯一离散规则计算：两项都通过才加 1 星，其他情况加 0 星。不得以某一个整体美感分数同时冒充两项验证通过。

## 4. 本轮已实现的产品与代码约束

1. 筛选顺序为“全部 / 智能选图 / AI 弃选区 / 待人工复核”。
2. `reviewPolicy.ts::reviewResultBucket` 集中决定分区：已确认 AI 1–5 星进入智能选图，已确认 AI 0 星进入 AI 弃选区；需要复核及既有人工结果归入待人工复核。三个区互斥且覆盖全部。
3. 弃选是可审查的结果分区，不删除照片。人工恢复沿用现有编辑、保护和写入流程。
4. `mode_policy.rs` 移除人像加权参数；`mode_scoring.rs` 移除人像连续换星阈值及旧理由分支。人像只通过 `portrait_rating_adapter.rs` 调用 `portrait_rating.rs`；误入旧通用评分入口会显式失败，并有回归保护。
5. 其他拍摄模式继续使用各自既有规则。旧二分类训练脚本与历史校准记录属于追溯材料，不参与当前五档运行时评分；不删除冻结标签、原图或历史审计记录。

上述分区与旧路径清理均位于前后端智能选图 feature 内，没有改上游 RapidRAW 文件。该阶段没有添加依赖或模型权重；随后质量模型的接入见第 7 节。复用既有复核策略、结果组件和离散评分模块，没有增加第二套状态管理。

## 5. 下一步与验收边界

本轮已经让 eDifFIQA(T) 通过现有 ONNX Runtime/Core ML 路径输出观测结果，并接入应用的人像分析和独立回放入口。下一步是独立的清晰度校准与盲测；光学和构图的通过条件随后分别验证。OFIQ 仍为离线对照候选，暂不引入整套 C++ 依赖。

实施与联调需要满足：

- 清晰度使用单独标签，不能复用第 001–003 批的表情星级作为答案；优先判断清楚与明显模糊，人工难判的边界样本单独记录。
- 原始人像只读；新增观测结果另存并记录模型、预处理、阈值和数据版本。
- 校准与盲测按人物和拍摄组隔离，覆盖清晰背景但脸失焦、背景虚化但脸清晰、侧脸、小脸、暗光、高噪声和美颜。
- 同时报告清晰照片误弃率、模糊照片漏检率、无法确定比例及每种场景样本量；不得仅靠扩大无法确定比例提高准确率。
- 在查看盲测答案前固定通过条件；尚未制定自动清晰度分类数值门槛，已有推理与模糊敏感性检查不是分类准确率。
- 用户暂时不用重新标表情或准备第 004 批；需要人工配合时，按[协作手册](./EXPRESSION_CALIBRATION_COLLABORATION_PLAYBOOK.md)只给一个已准备好的操作入口。

## 7. 代码接入与工程验证（2026-09-08 续接）

### 已落地行为

1. macOS Debug 预检增加可选 eDifFIQA(T) 模型，校验固定哈希并实际试运行。缺失或失败不阻断既有眼睛/表情链路，不联网下载，不放开 ORT CPU EP 回退。
2. 显式人像模式逐张收集：YuNet 五点对齐质量分、面部内侧 ROI 的原尺度/受控尺度拉普拉斯、Sobel 能量、加模糊后的细节保留比。小脸、侧脸、无效/越界脸框、无效对齐点、模型不可用及推理失败各有独立原因，不用数值 0 冒充缺失。
3. 整图与脸部新增 RGB8 曝光/色彩观测：高光/暗部裁切估计、各通道裁切、平均 RGB、亮度分位数和局部对比度。固定步长采样限制开销并保留被采样像素的裁切值；这不是 RAW 直方图、肤色正确性或创作意图判断。
4. 新增人脸中心与三分交点、黄金交点、画面中心的距离、脸部占比及上方余量。它们仅为几何观测；尚未接入 SAMP-Net/MUSIQ，也没有把“靠近三分线”当作审美通过。
5. 观测随 `ReviewResult.portraitQuality` 传到复核面板，展示为“新质量证据（待校准）”。评分主体标识复用实际人像主体选择：未指定人物时选最大的可靠脸；指定人物时仅显示已确认的目标，不另建一套选人规则。
6. 应用观测固定记录 `renderedRgb8` 和输入尺寸；独立诊断记录 `decodedRgb8`、原文件哈希、模型与规则版本。二者不可直接混作同一批阈值数据。
7. 当前生效的人像清晰度阈值、眼睛/五档表情映射及离散打星公式不变。新观测没有评分入口；联合光学/构图仍为 +0，实际上限仍为 4 星。
