### 1.10 2026-08-21 表情优先门禁与组件评测

### 1.11 2026-08-21 表情质量连续评分与 v002 覆盖率修正

- `ai-run-v002` 的 130 张照片全部完成分析，但 4.4 策略只写入 17 份侧车。根因不是漏跑：37 张明确低质量表情和 76 张不确定表情都被错误解释成“未通过门禁”，因此只有 17 张高置信可用表情进入组合。该语义与“表情完成评估后按模式权重参与综合评分”不一致。
- macOS Debug 策略升为 `qraw-smart-culling-policy-4.5-macos-expression-quality-calibration`，模型契约升为 `qraw-expression-quality-linear-synthetic-0.3`。可靠单帧现在输出 `[0, 1]` 连续表情质量代理；低分仍是有效证据并进入固定权重组合，只有遮挡、姿态或关键点几何导致质量分不可用时才保持 0 星人工审核。群像指定 A/B/C 时，每名指定人物都必须具有质量分。
- 130 张校准集回放中，表情可评分覆盖由 54/130 提高到 105/130；按质量分 `0.5` 仅作组件可用/不可用诊断时，通过 29 张中人工 3 ～ 4 星 27 张，不通过 76 张均为人工 1 ～ 2 星，25 张几何不可靠保持未知；以 `(人工星级 - 1) / 4` 为归一化目标的已评分 MAE 为 0.161。两批数据均参与过校准，这不是盲测结论。
- 最终综合自动决定为 48/130，另有 82 张人工审核：其中 25 张确实缺表情质量分，57 张已经完成表情评分但因构图证据仍不可用、固定权重区间跨越最终星级而复核。不得把后 57 张再次统计成“表情未识别”，也不得为制造侧车覆盖率而填充构图中间分。
- 旧 200 张眼态回归的 `eyeCandidate`、逐脸左右眼结果和原 34 张一星集合继续保持 0 差异。表情 0.3 仍只读取非眼 Blendshape 与 `tongueOut`，不读取文件名、路径、哈希或人工星标；没有新增模型和依赖。严格按场景留出的连续排序泛化仍只达到中等水平，不能宣称已具备可靠的 4/5 星表情审美区分能力或 95% 可信度。

## 2. 已确认且不可擅自改变的规则

### 2.1 上游隔离与页面边界

- 上游为 CyberTimon/RapidRAW；
- 智能选图是 QRaw 独立二开 feature；
- 前端业务主体只能位于 src/features/smart-culling/；
- Rust 业务主体只能位于 src-tauri/src/features/smart_culling/；
- 上游文件只允许统一挂载、注册、通用插槽、通用契约和必要透传；
- 禁止把评分、人物识别、锁定、分组或写入逻辑散落到上游组件和公共工具；
- 后续同步上游时保持上游提交原貌，由独立 feature 适配接口变化；
- 页面只维护中部，左侧来源栏和右侧调整栏不可修改。

### 2.2 文件夹范围

- 用户需要选中并展开当前文件夹；
- 处理该文件夹直接包含的全部支持图片；
- 不进入子文件夹，不递归；
- 子文件夹应被明确忽略，不作为失败项；
- 受保护资产即使位于当前层级，也不得被系统修改。

### 2.3 模式范围

每次只能选择一种模式，只保留：

1. 自动；
2. 风光；
3. 人像；
4. 环境人像；
5. 群像。

删除街拍、动物、建筑、产品、银河。删除必须覆盖前后端常量、类型、白名单、评分分支、文案、
原因码和测试，不能只在页面隐藏。

指定关键人物只在人像、群像显示。自动、风光和环境人像完全隐藏，后端也必须拒绝非法的
“模式 + 关键人物”组合。

### 2.4 绝对星级与相似组

- 每张照片在当前模式下独立计算绝对质量；
- 1 至 5 星只由绝对质量映射；
- 相似组内仍按每张照片的绝对质量排序；
- 组内排名和“组内首选”是独立信息，不能加星、降星或改变星级；
- 两张同组照片都足够优秀时，可以同时获得相同高星；
- 照片换文件夹或换分组，星级不能因此改变；
- 0 星表示尚未形成可采用的系统星级，或需要人工审核。

实现时必须分离三种语义：

1. 绝对质量分；
2. 仅由绝对质量映射的星级；
3. 相似组排名与首选。

当前已由 `mode_scoring.rs` 的 `rating_for_mode` 仅依据解析后模式与绝对分数映射星级；`scoring.rs` 中的排名和推荐数量不再参与星级决策。

### 2.5 人工锁定是最高安全底线

- 只有用户操作可以产生锁定，系统永远不能自动锁定；
- 用户设置星级、修改 AI 星级或手动清零到 0 星后，都立即锁定；
- AI 首次写入且用户未修改的结果不锁定；
- 用户可主动解锁，解锁持续生效；
- 解锁后系统再次写入也不能恢复锁定；
- 只有用户再次操作才重新锁定；
- RAW/JPEG 任一成员的人工操作锁定整个资产；
- 人工审核中的手动打星也锁定整个资产。

必须双重保护：

1. 建立任务清单时读取锁定和来源状态，排除受保护资产；
2. 真正写入前重新读取元数据，检查锁定、来源、版本和并发人工修改。

读取失败、来源不明、成员状态冲突或版本过期时，必须保留现状并明确报告，不能猜测后覆盖。

现有 domain/metadata.rs 已具备人工来源推断、用户修改 AI 结果、手动清零和 RAW/JPEG 资产保护基础，
应在其上扩展，不能另建第二套来源判断。

### 2.6 RAW/JPEG

- 同名且确认配对的 RAW/JPEG 显示为一个资产组；
- 默认显示 JPEG，没有 JPEG 时再显示 RAW；
- 星级、锁定、人工审核和写入保护属于整个资产组；
- 不允许同一资产出现互相矛盾的用户星级；
- 配对不明确时不得猜测。

展示成员与分析成员应在契约中分开表达。技术质量是否优先分析 RAW 标准化渲染属于当前研究建议，
尚需成对样片验证，不阻塞默认展示 JPEG 和资产级保护。

### 2.7 指定关键人物

- 可选择一位或多位，用人物 A、B、C 区分；
- A/B/C 只区分身份，不自动表示优先级；
- 一张脸不能同时满足多个指定人物；
- 照片包含全部指定人物后，才进入当前人像类模式的二次评分；
- 明确缺少任意一位时进入低星范围；
- 疑似匹配、身份歧义或不可可靠识别时进入独立人工审核；
- 人工审核提示“疑是关键人物”，系统保持 0 星，由用户手动打星；
- 用户手动确认结果不会自动扩充持久人物库；
- 群像使用同一规则。

现有 YuNet、SFace 和 face_identity.rs 已有对齐、向量、相似度及一对一分配基础，应扩展复用。

## 3. 五个可选模式与七个最终策略

用户仍只选择自动、风光、人像、环境人像、群像五个拍摄模式；最终评分必须先解析成以下七个策略。清晰门禁只在“确定不清晰”时直接返回 1 星；不确定时继续计算。后续证据按冻结权重形成保守分数区间，缺失项不得当中间分，也不得对已有项重归一化。

| 解析策略          | 第一层清晰门禁 | 门禁后固定权重                                           | 人物规则                                                         |
| ----------------- | -------------- | -------------------------------------------------------- | ---------------------------------------------------------------- |
| 人像              | 人物清晰       | 眼态 40% + 表情 40% + 光学 10% + 构图 10%                | 无指定人物时评估主体；有指定人物时只评估全部确认身份             |
| 群像 + 指定人物   | 指定人物清晰   | 指定人物眼态 40% + 表情 40% + 光学 10% + 构图 10%        | A/B/C 必须一对一且全部确认；疑似/歧义/未知保持 0 星人工复核      |
| 群像 + 无指定人物 | 整图清晰       | 光学 90% + 构图 10%                                      | **忽略所有人脸、人物清晰、眼态和表情证据**                       |
| 环境人像          | 整图清晰       | 光学 50% + 构图 35% + 人物清晰 5% + 眼态 5% + 表情 5%    | 不允许选择指定人物；人物证据只占已确认的 15%                     |
| 风光              | 整图清晰       | 光学 50% + 构图 50%                                      | 忽略远处或背景人物的眼态与表情                                   |
| 自动 + 有人       | 整图清晰       | 人物清晰 50% + 眼态 15% + 表情 15% + 光学 10% + 构图 10% | 不允许选择指定人物；人物状态为加权证据，不是人像模式的眼态硬上限 |
| 自动 + 无人       | 整图清晰       | 光学 50% + 构图 50%                                      | 若仍有较弱人物线索，不得强行当作无人高星，转人工复核             |

眼态上限只适用于人像和“群像 + 指定人物”：单眼闭合、眨眼瞬间、半闭眼或普通闭眼最高 1 星；有意闭目姿态候选最高 3 星。侧脸眼态记 `unknown`；脸部遮挡或看不清属于更严重的人物清晰门禁问题。环境人像和自动有人仅按 5%/15% 加权眼态，不应引入人像式硬上限。

表情只判断技术可用瞬间，不评价情绪、吸引力或“必须微笑”。它只读非眼面部动作证据，不得改写眼态核心。构图模型未放行时必须表达为缺失区间，不得以三分法、居中或对称等手写规则冒充完整审美结论。

## 5. 技术研究结论与边界

### 5.1 优先复用

- YuNet：继续做人脸检测，补多尺度分块和去重；
- SFace：继续做人物 A/B/C 身份匹配，基于真实照片重新校准；
- 眼态：复用已冻结的 FaceMesh 密集眼睑几何 + Blendshape 眨眼系数交叉证据；当前契约为 `qraw-eye-model-contract-1.0` + `qraw-eye-policy-1.1`，表情、光学和构图不得改写；
- 现有 metadata、catalog、asset、scoring 和 API 契约：在原体系扩展；
- ONNX Runtime：继续作为唯一生产推理运行时。

### 5.2 候选能力

| 能力         | 当前优先候选                                 | 用途                         | 状态                                                |
| ------------ | -------------------------------------------- | ---------------------------- | --------------------------------------------------- |
| 人物主体     | RT-DETRv4-S，RT-DETRv2 备选                  | 自动路由、环境人像门槛       | 未接入                                              |
| 通用视觉特征 | DINOv2 ViT-S/14                              | 相似组、构图、自有排序头     | 未接入                                              |
| 无参考画质   | ARNIQA                                       | 技术质量辅助证据             | 隔离导出通过；QRaw 严格运行时失败、未授权、未进生产 |
| 人脸关键点   | MediaPipe FaceMeshV2 ONNX；RTMPose face 备选 | 眼睑、姿态、嘴型、对称、遮挡 | macOS Debug 已接校准适配；Release 不可用            |
| 面部动作     | MediaPipe BlendshapeV2 ONNX                  | 冻结眼态 + 只读非眼表情描述  | macOS Debug 已接校准适配；Release 不可用            |

每个候选必须单独完成：许可与权重再分发审查、参考输出、ONNX 导出、Core ML 和 DirectML 完整图、
数值一致性、真实照片准确率、速度、内存、显存和包体评估。

未经用户批准不得新增依赖。InsightFace 免费预训练模型、MobileCLIP 官方权重等存在商业分发限制，
不得直接打包。MediaPipe 官方 TFLite 只作研发参考；ONNX 转换必须先与官方输出完成逐图数值一致性验证，
不得仅凭社区转换文件进入生产评分，也不引入第二套生产运行时。

FaceMeshV2 + BlendshapeV2 已完成隔离工程 POC：官方 TFLite 契约核对、社区 ONNX
数值对齐、派生图 CPU 零误差、资产 SHA 固定，以及项目内置 ONNX Runtime 1.22 下禁止
CPU 回退的 macOS Core ML 加载与推理。macOS Debug 可使用这些证据运行冻结眼态契约和只读非眼表情序列适配；模型仍不在 Tauri 生产资源中。Release/其他平台必须显式输出 unavailable/`unknown`。仍缺 Windows DirectML、真实连拍标注集、阈值校准与摄影师验收；不得将 Debug POC 结果写成生产放行。

### 5.3 当前算法方案

- 自动路由：人物检测与人脸检测联合判断，灰区双路评分，跨星级则审核；
- 关键人物：多尺度 YuNet、高质量参考、SFace 一对一分配、高/灰/低三区间；
- 眼态：使用已冻结的密集眼睑几何 + 眨眼系数交叉证据；冲突、侧脸或遮挡记 `unknown`，后续功能不得调整该契约；
- 表情：使用只读非眼面部动作证据；只有身份已 confirmed 的指定人物可在同一相似组内比较稳定瞬间。无指定人物不得用“每帧一张脸”冒充身份跟踪；情绪分类置信度不得代替稳定性证据；
- 相似组：时间/序号候选、现有感知哈希、DINOv2 全局和局部特征、灰区几何验证；
- 聚类：高精度优先，锚点或完整连接，禁止链式漂移；
- 序列保护：包围曝光、全景接片、焦点堆栈和有意义的动作变化不得误合并；
- 技术质量：全局缩略图加高分辨率主体局部，多区域清晰、模糊、噪声、曝光和画质证据；
- 构图：DINOv2 特征加 QRaw 真实样片的小型成对排序头，可解释规则只作软证据。

详细候选来源和历史论证见旧需求基线。旧基线若仍描述十模式、递归扫描或排名改变星级，均以本文为准。
