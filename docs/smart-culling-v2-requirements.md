## 0. 文档效力

本文档是智能选图“做什么”的唯一正式产品事实源。技术架构回答“如何做”，实施清单回答
“按什么顺序和证据验收”，UI 基线约束用户可见页面与交互。需求访谈确认稿只保留为决策来源记录，
不得与本文并行指导代码。

发生冲突时：

1. 本文决定产品行为、边界和验收目标。
2. 技术架构不得缩减本文要求；不可行项必须返回产品决策，不能自行降级。
3. 实施清单必须逐项追踪本文和技术架构，未有证据不得标记完成。
4. UI 基线不得改变本文语义，但可以把分阶段能力展示为最终目标界面。
5. `AGENTS.md` 和 `docs/feature-integration-guidelines.md` 决定代码隔离、复用和验证纪律。

## 1. 产品目标和客户端边界

智能选图用于摄影工作流早期初筛，减少摄影师逐张检查成本，同时优先保护不可重现、具有情绪、
叙事或交付价值的照片。产品最终随 QRaw macOS 和 Windows 客户端安装包交付。

核心目标：

- 推荐技术质量、瞬间质量和故事价值较高的照片。
- 在连拍与相似照片中保留 3-5 张具有不同价值的候选，而不是只留一张。
- 保护关键人物、关键场景、关键事件和拍摄组合。
- 可信度不足或创作意图不明的照片进入待确认，不直接淘汰。
- 每项判断提供简短、真实、可追溯的原因。
- 用户以低学习成本完成“启动、配置、等待、复核、确认”完整流程。

Linux、Android、云服务、外部模型 API 和浏览器版不属于本轮正式客户端交付范围。

## 2. 核心约束

- 完全离线、本地运行；原图、缩略图、人脸、特征向量和分析结果不得上传。
- 核心模型随 macOS/Windows 安装包分发，首次使用不下载；模型只随新版客户端更新。
- 效果与召回优先，但模型组合必须同时给出安装包、磁盘、内存、显存和启动预算。
- 最终产品不允许静默切换 CPU 或能力不完整路径；GPU-only 是待 P0 基准证明的产品约束，
  不是已经验证的发布结论。
- 模型、运行时、契约或硬件能力不足时只禁用智能选图，不影响 QRaw 其他功能。
- 分析结果在用户最终确认前不得写入 `.rrdata`。
- 不删除、移动或复制原图，不生成 PDF，不维护任务历史或撤销栈。
- 全局同时只允许一个运行中或待复核的智能选图任务。
- 人工结果始终优先，系统不得覆盖或绕过用户干预。

## 3. 固定用户流程

1. 用户在 Library 打开本地图片文件夹。
2. 点击“智能选图”。
3. 系统完成设备、运行时和模型预检并显示精简配置。
4. 用户每次选择一个拍摄类型，可按需选择关键人物。
5. 用户点击“开始选图”，系统完全离线分析当前文件夹及全部子文件夹。
6. 分析期间用户可在 Library 只读浏览和切换文件夹。
7. 完成后只显示通知和“结果待复核”状态，不自动跳转。
8. 用户主动进入复核，确认、修改或取消部分/全部建议。
9. 用户最终确认后，系统安全写入被采用资产对应的 `.rrdata`。
10. 写入允许部分成功；结果页列出失败项并允许重试。

## 4. 配置与拍摄类型

### 4.1 用户可配置项

- 拍摄类型：每次必须选择一个，默认“自动 / 混合场景”。
- 关键人物：仅适用模式显示，可跳过。

不向用户提供范围切换、当前选择、目标 N、目标 N%、筛选强度、创作容忍度或技术阈值。递归范围、
推荐数量和筛选策略由系统自动决定。

### 4.2 拍摄类型

- 风光
- 人像
- 环境人像
- 群像
- 街拍 / 纪实
- 动物 / 鸟类
- 建筑 / 空间
- 产品 / 静物
- 星空 / 银河

自动模式可逐张路由主模式和辅助模式。复核页允许纠正单张照片或相似组的拍摄模式。

## 5. 分析范围、格式与拍摄资产

### 5.1 目录范围

- 分析范围固定为任务启动文件夹及全部子文件夹。
- 每个子文件夹独立进行相似分组、故事组织和组内推荐。
- 复核页汇总全部目录，并支持“文件夹树 → 当前文件夹故事段落”两级筛选。

### 5.2 格式

- 复用 QRaw 当前能打开的静态图片格式。
- 明确跳过 GIF、TIFF 和 TIF；正常跳过不算失败。
- 声称支持但无法解码的单张图片算失败，跳过并说明原因。

### 5.3 RAW/JPEG 资产

- 同目录、同基础文件名的 RAW 与 JPEG/JPG 视为一个拍摄资产，只分析、展示一次。
- 有 RAW 时 RAW 为主资产，最终只写 RAW 的 `.rrdata`。
- 只有 JPEG、PNG 或其他非 RAW 静态图片时，写该文件自己的 `.rrdata`。
- 任一配对成员存在人工星级或人工颜色标签时，整个资产受保护并跳过。
- 同名导出图、多 JPEG 等歧义无法安全确认时不得猜测配对，应跳过并报告。

## 6. 分析画面状态

智能选图评估任务启动时的当前成片状态，必须包含已生效的：

- 全局调色、LUT
- 裁剪、旋转和几何调整
- 局部蒙版、修复和降噪
- 其他 QRaw 非破坏性处理

已有编辑但没有人工星级或颜色标签的照片仍参与分析。实现必须复用 QRaw 现有渲染、调整与缓存管线，
不得复制一套不一致的调色或几何算法。具体输入端口属于 P0 架构与性能验证门。

## 7. 人工保护与结果来源

当前星级和颜色标签只有两种来源：

- `AI`：智能选图建议，用户未修改。
- `人工`：用户在普通 Library 手动操作，或修改了智能选图建议。

历史 `.rrdata` 中有星级或标签但没有可靠 AI 来源时按人工处理。

以下任一操作都使整张照片成为受保护人工结果：

- 普通页面手动设置或取消星级。
- 普通页面手动设置或取消颜色标签。
- 复核页修改 AI 星级或颜色标签，包括把它们取消。

受保护资产在后续智能选图中不分析、不展示建议、不修改 `.rrdata`。调色、裁剪和蒙版本身不构成
人工保护。用户修改 AI 结果后，来源立即改为人工，清除 AI 原因和旧建议追溯信息。

用户仅在复核页取消勾选表示“本次不采用”：不写入，也不产生人工保护。取消全部勾选等同完全放弃。
普通 Library 不提供“批量取消智能选图”入口。

## 8. 输出语义

每张成功分析且最终采用的图片同时获得：

- 1-5 星当前结果
- 绿色“精选”、黄色“待确认”或红色“淘汰建议”颜色标签
- AI 或人工来源
- 最多两条简洁原因
- 可信度、拍摄模式、模型版本、结果 ID 和确认时间

星级含义：

- 5 星：强烈推荐
- 4 星：推荐
- 3 星：需要用户确认
- 2 星：质量偏弱但可能仍有价值
- 1 星：淘汰建议

星级是独立质量判断，不由颜色机械决定。低可信度和受保护拍摄组合不得直接标红。

原因必须由实际证据、阈值或组内比较通过确定性模板生成，不使用无法追溯的自由文本。用户修改后，
人工结果不再显示 AI 原因。

## 9. 相似组、拍摄组合与故事线

### 9.1 普通相似组

- 连拍或高度相似组根据组大小、质量差距、表情、动作、构图和故事差异推荐 3-5 张。
- 小于 3 张的小组按实际数量处理。
- 组内其他图片仍获得星级、颜色标签和原因建议。

### 9.2 受保护组合

HDR、全景、景深合成、延时、星空堆栈和有意连续动作不能因相似而淘汰。自动识别属于 P2 效果能力；
准确率通过前不得把普通相似度包装成可靠组合判断。识别到的组合整体进入待确认。

### 9.3 故事线

文件夹/故事段落工作台是 P3 体验增强，最终视觉以已验收 UI 为准。它可晚于 P1 数据安全闭环，
但生产页面必须使用当前任务真实图片、目录、分组、评分和统计。

## 10. 关键人物与隐私

- 关键人物属于 P2 效果能力，仅在自动、人像、环境人像、群像、街拍/纪实模式显示。
- 用户按“选照片 → 打开照片 → 点击具体人物”主动选择，不先自动聚类后要求确认。
- 支持多选，选择顺序即优先级。
- 人物样本和特征只在当前任务内存/临时区使用。
- 任务完成、放弃、失败、应用退出或异常重启后清除。
- 不保存身份信息，不推断敏感属性，不上传人物数据。

## 11. 后台任务与取消

- 分析在后台运行，用户可以只读浏览并切换文件夹；任务范围仍固定为启动根目录。
- 分析期间禁止编辑、打星、设置标签、移动/重命名/删除/导入文件，以及导出、HDR、全景、降噪等重任务。
- 进度面板显示真实阶段、已完成数、总数、动态 ETA 和取消按钮，不得模拟进度。
- 用户取消时停止新增重任务，保留已完成结果供复核；未完成图片保持原样。
- 取消操作目标为 2 秒内停止新增重任务。
- 应用崩溃或关闭后不恢复未完成任务；下次启动清理临时结果和人物特征。

## 12. 复核与确认

复核页必须支持：

- 默认勾选全部成功结果；单选、多选、全选和取消部分/全部。
- 修改单张星级、颜色标签和单张/相似组拍摄模式。
- 展开普通相似组与受保护组合。
- 查看原因、可信度、失败、跳过与冲突说明。
- 按文件夹层级和故事段落筛选。
- 最终统一确认写入。

失败项不可勾选。确认前操作只作用于当前任务临时结果。离开未确认复核页或完全放弃必须二次确认，
清除临时结果和人物特征，不写 sidecar。

完整页面、异常分支和桌面尺寸规则见 `docs/smart-culling-v2-ui-lifecycle.md`。

## 13. 普通 Library 结果展示

网格与列表复用同一紧凑信息结构，显示：

- 当前星级
- 当前颜色标签
- AI 或人工来源
- AI 结果的一行简洁原因

人工结果不显示 AI 原因。内容过长时省略，悬停显示全文。

## 14. `.rrdata` 持久化

### 14.1 写入内容

最终采用结果至少保存当前星级、当前颜色标签、来源、是否被用户修改、原因、可信度、模式、模型版本、
结果 ID 和确认时间。每张照片只保留当前结果，不维护多次智能选图历史。

### 14.2 数据安全

- 任务启动记录 sidecar 基线；最终确认前重新检查。
- 外部程序或其他流程修改的图片跳过，不覆盖新数据。
- 按拍摄资产决定唯一目标 sidecar，遵守 RAW/JPEG 规则。
- 每张 sidecar 只合并智能选图拥有的字段以及经用户确认的当前星级/颜色标签；保留 adjustments、EXIF、其他 feature 数据和同期人工修改。
- 写入采用同目录临时文件、同步和原子替换；单项失败不回滚其他成功项。
- 失败项列出具体原因并允许重试。

不提供最近一次任务撤销、撤销 journal 或历史快照。复核页勾选是唯一结果取舍入口。

## 15. 模型、设备与性能

### 15.1 候选设备范围

候选 macOS 范围：macOS 13+、Apple Silicon M1+，建议 16 GB 统一内存。
候选 Windows 范围：Windows 10/11 x64、DirectX 12 GPU，优先 NVIDIA GTX 16/RTX、AMD RX 6000+、
Intel Arc，建议 6 GB 显存和 16 GB 内存。

Intel Mac、Intel UHD 和老旧显卡暂不在候选范围。该范围必须经 P0 CoreML/DirectML、算子兼容、
显存/内存、温控和错误恢复基准后才能成为正式发布门槛。

### 15.2 性能目标

- 1000 张混合 RAW/非 RAW 在常见支持设备上的目标为 2-5 分钟。
- 5 分钟是工程目标；10 分钟只是最低设备失败边界，不是放宽后的目标。
- 优先复用当前渲染结果、缩略图、RAW 内嵌预览和缓存。
- RAW/JPEG 资产只分析一次，使用有界 GPU 批处理和按需高分辨率精查。
- 性能声明必须绑定设备、数据集、格式比例、缓存状态和模型版本。

未通过 P0 时不得通过模拟进度、减少分析内容或静默 CPU 回退宣称达标。

## 16. 语言与无障碍

- 第一版完整支持中文和英文，其他语言回退英文。
- 配置、进度、复核、错误和原因均使用 feature-local 翻译资源。
- 核心操作必须具备键盘焦点、屏幕阅读器名称和非纯颜色状态表达。

## 17. 准确率与发布门槛

当前没有真实摄影金标准，因此可以开发工程闭环，但不能宣称生产准确率达标。稳定发布至少满足：

| 指标 | 门槛 |
| --- | --- |
| 最终保留图进入“精选 + 待确认” | >= 99% |
| 最终保留图误入“淘汰建议” | <= 1% |
| 受保护拍摄组合召回 | >= 99% |
| 相似组最佳进入前三推荐 | >= 90% |
| 达到像素门槛的人脸闭眼 F1 | >= 0.90，并分层报告 |
| 关键人物和关键事件覆盖 | >= 95% |
| 1000 张目标设备端到端时间 | <= 5 分钟 |
| 取消响应 | 2 秒内停止新增重任务 |

比例指标按完整 shoot 切分和 bootstrap 95% 置信区间报告。未达标能力保持实验或关闭，不用文案规避。

## 18. 实施分层

- P0 技术验证门：GPU 推理、当前渲染状态输入、模型与安装资源预算、1000 张基准。
- P1 数据安全闭环：递归资产、配对、人工保护、来源、基线校验、复核确认与安全写入。
- P2 效果能力：九模式、关键人物、拍摄组合、分组评分和真实原因。
- P3 体验增强：故事线工作台和跨组复核效率。

分层只调整实现顺序，不取消最终目标。P0/P2 未验证的能力不得由占位数据或旧 V1 规则伪装完成。

## 19. 明确非目标

- 不删除、移动或复制照片。
- 不联网、不上传、不接外部模型服务。
- 不维护任务历史、PDF、预设、撤销栈或本地偏好学习。
- 不允许用户设置目标 N/N%、筛选强度或分析范围。
- 不在普通 Library 提供流程外批量取消入口。
- 不评价人物外貌、吸引力、年龄、族群、残障或情绪是否正常。
- 不在低可信度时强制淘汰。

## 20. 尚未冻结的技术事项

- 最终模型组合、运行时和模型权重来源。
- CoreML/DirectML 的正式执行器和算子覆盖。
- 各模式权重、阈值、训练集和真实摄影金标准。
- 安装包增量、磁盘、内存和显存硬预算。
- 正式设备矩阵与真实性能结果。
- RAW/JPEG 多成员和同名导出歧义细则。

这些事项进入技术 Gate，不得由实现自行猜测或通过降低产品语义绕过。
