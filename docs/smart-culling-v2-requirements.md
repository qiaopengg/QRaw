## 0. 文档效力

智能选图只保留三份当前文档：本产品需求、技术架构和任务执行清单。三者分别回答“做什么”、
“如何做”和“按什么顺序验收”，旧需求、旧技术方案、讨论稿和历史 Q&A 不再作为实施依据。

发生冲突时按以下顺序处理：

1. 本文档决定产品行为、边界和验收目标。
2. 技术架构决定实现约束、选型门槛和安全边界，不得缩减本文档需求。
3. 执行清单必须逐项追踪本文档和技术架构，不得引入二者之外的产品功能。
4. `AGENTS.md` 决定编码过程、复用、文件规模、依赖审批和验证纪律。

任何需求变化必须先修改本文档，再同步技术架构和执行清单，禁止只改代码或只改任务状态。

## 1. 产品目标

智能选图用于摄影工作流早期的照片初筛。系统需要减少摄影师逐张检查照片的工作量，
同时尽量避免遗漏具有情绪、叙事或交付价值的照片。

产品目标不是简单选出单张最高分照片，而是同时满足：

- 推荐技术质量和瞬间质量较高的照片
- 保留完整故事线、关键人物、关键场景和关键事件
- 在连拍和相似照片中推荐有不同价值的候选
- 识别需要人工确认的风险，不擅自淘汰不确定照片
- 为每项判断提供简短、真实、可追溯的原因

核心错误策略为召回优先。错留一张低质量照片只会增加少量复核成本，错过一张不可重现
的好照片则可能无法挽回。因此，可信度不足或创作意图不明确的照片必须进入待确认，不能
直接进入淘汰建议。

## 2. 基础产品约束

- 默认完全离线、本地推理，后续允许通过独立适配层接入外部模型
- 支持上游当前发布平台：macOS、Windows、Linux 和 Android；能力可以按平台验证结果降级，但不得静默改变评分语义
- 支持常见 RAW、JPG、JPEG、PNG 图片
- 默认分析当前文件夹的全部受支持图片，并允许改为仅分析当前选中图片；第一版不递归子文件夹
- 同名 RAW 与 JPEG 视为同一拍摄资产，避免重复分析和重复评分
- 评估拍摄质量时使用原始拍摄资产或其嵌入预览，不使用后期调整后的渲染结果替代原始证据
- 系统评分与摄影师人工星级严格分离
- 系统不得覆盖人工星级，不得删除照片
- 系统不得自动写入颜色标签或用户标签；颜色标签继续由用户自行定义含义
- 分析结果必须经过用户复核和确认后才能写入
- 每张照片只保留最新一次用户确认的智能结果
- 只保留最近一次应用所需的临时撤销快照；下一次确认后覆盖
- 不维护多次任务历史和历史 PDF 报告
- 目标处理时间为 2 至 5 分钟，并显示来自真实任务数据的处理进度
- 单个稳定 ActiveSet 的全部模型与策略资产不得超过 2 GiB；下载候选或保留上一版本需要额外空间时必须预检并提示
- 核心能力缺失时禁止启动；可选能力缺失时必须说明受影响功能，由用户选择降级继续或取消，禁止静默伪造完整分析

## 3. 任务模式

### 3.1 默认混合场景

`混合场景` 是默认模式。系统逐张识别内容，再将照片路由给对应的模式评分器。同一张照片
允许拥有一个主模式和最多两个辅助模式，避免将环境人像、人与动物、人物与建筑等复合画面
强行归入单一类别。

用户也可以选择固定模式，让整个任务使用明确的拍摄意图进行评估。

### 3.2 支持模式

- 风光
- 人像
- 环境人像（风光 + 人像）
- 群像
- 街拍 / 纪实
- 动物 / 鸟类
- 建筑 / 空间
- 产品 / 静物
- 星空 / 银河

用户可以在复核阶段修改单张照片或相似组的主模式。

## 4. 评分输出

系统内部使用 0 至 100 分进行计算，并映射为带明确 AI 来源的 1 至 5 星建议。摄影师人工星级
始终拥有更高优先级。

每张照片至少输出：

- 综合质量分
- AI 星级建议
- 精选、待确认或淘汰建议
- 主模式和辅助模式
- 可信度
- 最多两个优点、两个风险和一个组内结论
- 相似组或拍摄组合信息
- 组内综合最佳、专项最佳和备选身份
- 故事线与内容覆盖贡献

用户可以选择以下任务目标：

- 不限制数量，只按质量分级（默认）
- 大约保留前 N 张
- 大约保留前 N%

目标数量只影响推荐分布，不能把低可信度照片强制归入淘汰建议。

## 5. 评分维度

综合结果由独立维度融合产生，禁止由单一美学模型直接决定星级。

### 5.1 通用维度

- 技术质量：解码完整性、清晰度、曝光、噪声、非预期运动模糊
- 主体质量：主体清晰度、遮挡、裁切和可辨识程度
- 瞬间质量：表情、姿态、动作阶段和多人同步程度
- 构图与美学：视觉平衡、主体关系、背景干扰和画面完成度
- 模式专项质量：由主模式和辅助模式提供
- 组内竞争力：在相似照片和连拍中的相对表现
- 多样性与故事贡献：对人物、场景、时间和构图覆盖的贡献
- 可信度：场景、主体和专项判断的可靠程度

### 5.2 模式侧重点

- 风光：整体清晰度、动态范围、地平线、层次和空间构图
- 人像：眼睛与面部清晰度、表情状态、姿态和背景干扰
- 环境人像：人物质量、环境质量及人物与环境的叙事关系
- 群像：有效人脸比例、关键人物、闭眼比例和表情同步程度
- 街拍 / 纪实：瞬间、人物关系和叙事优先，降低对轻微技术缺陷的惩罚
- 动物 / 鸟类：眼部、头部、主体清晰度、姿态、动作阶段和遮挡
- 建筑 / 空间：垂直线、透视、对称、几何关系和空间曝光
- 产品 / 静物：材质细节、主体边缘、反光、高光和背景洁净度
- 星空 / 银河：星点锐度、拖线、噪声、光害、前景和银河结构

## 6. 高分与完整故事线

系统不能只按综合分从高到低截取照片。它还必须识别时间段、场景、人物、事件和构图变化，
在质量接近时优先保留能够补全故事的信息。

故事线策略至少需要：

- 避免结果全部集中在同一人物、同一动作或同一角度
- 保留环境建立镜头、关键事件、人物关系和必要过渡镜头
- 在相近分数下优先选择姿态、角度、构图和内容不同的照片
- 同时标明照片的质量价值和故事贡献，避免用故事分掩盖严重技术问题

## 7. 相似照片与拍摄组合

### 7.1 普通连拍和相似组

相似组不能只强制选择一张。系统应根据实际内容提供：

- 综合最佳
- 表情最佳
- 技术质量最佳
- 具有不同叙事或动作价值的备选照片

组内推荐还需要执行多样性约束，避免所有候选都来自几乎相同的动作和构图。

### 7.2 受保护的拍摄组合

以下序列虽然视觉相似，但默认不能作为普通重复照片进行淘汰：

- HDR 包围曝光
- 全景接片
- 景深合成
- 星空堆栈
- 延时序列
- 有意连续记录的动作过程

这些照片应标记为“拍摄组合”，整体进入复核。系统可以说明单张技术风险，但不得仅因相似度
给出淘汰建议。

## 8. 创作意图保护

系统需要区分技术事故、可能的创作意图和无法确定三种情况。

支持以下创作容忍度：

- 保守：优先保护可能有价值的瞬间，更多结果进入待确认
- 均衡：在技术质量和创作表达之间平衡（默认）
- 严格：提高技术质量门槛，但仍不得自动淘汰低可信度照片

暗调、颗粒、轻微运动模糊、局部失焦、闭眼或倾斜构图可能是有意表达。仅检测到这些特征时，
不得直接判定为淘汰建议。

在人像、街拍、婚礼和家庭类画面中，明显的情绪或不可重现瞬间可以补偿轻微失焦、噪声和曝光
问题，但不能补偿文件损坏、严重糊脸或主体完全不可辨识。

## 9. 表情检测

功能统一命名为“表情检测”。它描述摄影瞬间中的人像状态，不评价人物本身是否正常。

客观检测范围包括：

- 闭眼和眨眼中间态
- 面部模糊
- 面部遮挡
- 视线方向
- 嘴部捕捉中间态
- 头部姿态
- 多人表情同步程度

微笑、严肃和强烈情绪只能作为描述或用户偏好，不能作为默认好坏判断。系统不得评价人物的
长相、吸引力、年龄、族群、残障或情绪是否正常。

## 10. 关键人物

群像和活动任务支持用户可选地标记关键人物。系统在本地聚合同一人物，并在群像评分和故事线
覆盖中提高其优先级。

关键人物能力必须满足：

- 完全离线处理，默认不上传人脸或身份数据
- 用户可以跳过关键人物设置
- 用户可以清除本地人物聚合结果
- 不使用人物身份推断敏感属性

## 11. 本地偏好学习

V2 首个稳定版本纳入可重置的本地偏好学习，但不微调基础模型。

系统记录用户在复核阶段的接受、拒绝、改星、修改组内最佳和模式纠正，用于逐步调整：

- 各模式评分权重
- 创作容忍度
- 推荐数量倾向
- 用户对暗调、颗粒、运动感、情绪和构图的偏好

所有反馈默认只保存在本地。用户可以查看学习状态并一键重置。

## 12. 复核与应用

分析完成后必须进入复核流程，至少支持：

- 查看高分结果和故事线结果
- 按精选、待确认、淘汰建议、模式、原因和可信度筛选
- 展开普通相似组和受保护拍摄组合
- 修改星级、状态、主模式和组内最佳
- 接受全部、按组接受、仅应用部分结果或拒绝全部
- 明确提示淘汰建议不会删除文件

未经确认的结果不得写入 `.rrdata`。确认后只保留最新智能结果，并生成仅供最近一次应用撤销
使用的临时快照。下一次确认后覆盖旧智能结果和旧撤销快照。

交互基线为：Library 顶部工具区提供智能选图入口；配置使用聚焦的任务设置界面；分析期间显示
真实进度且允许取消；完成后进入与 Library 视觉语言一致的全屏复核工作区。桌面端优先支持高密度
批量复核，Android 使用同一信息结构的响应式布局，不建立不同业务流程。最终布局以用户选定的
Product Design 方案为视觉基线，但不得改变本节功能范围。

用户已选择“方案 3：故事线序列工作台”作为最终视觉基线，参考图为
`docs/assets/smart-culling-v2-story-workbench.png`。实现必须保留以下信息架构：

- 顶部显示本次任务、结果统计、视图切换、筛选和应用入口
- 左侧按时间顺序显示故事段落及每段照片数量，支持快速切换场景
- 中央按故事候选、受保护拍摄组合和连拍优选组织真实 Library 缩略图
- 右侧集中显示故事贡献、确定性原因、技术信息、AI 建议与摄影师手动星级
- 桌面端支持高密度批量复核，窄屏端按“序列导航、缩略图、详情”逐层呈现，不删减确认能力

参考图中的婚礼照片和数量只用于说明布局，不是固定素材或产品默认数据。实现必须使用当前任务的
真实图片、分组、评分和统计结果，并保持现有 QRaw 深色、紧凑、低圆角视觉语言。

## 13. 原因说明

原因必须由实际检测指标、阈值和组内比较通过确定性模板生成，不使用无法追溯的自由文本。

示例：

- 眼睛清晰，面部曝光正常
- 主体存在轻微运动模糊
- 同组 8 张中表情同步程度最高
- 画面具有关键事件价值，保留为故事线候选
- 检测到街拍场景，轻微运动模糊未作为主要扣分项
- 未可靠识别主体，结果可信度较低

## 14. 性能与真实进度

目标是在中端及以上设备上，1000 张混合图片于 2 至 5 分钟内完成。正式验收前必须明确测试
设备、图片格式、分辨率和模式分布，不能只依据开发机结果宣称达标。

进度必须来自实际任务计数，至少包括：

- 资产准备和拍摄组合识别
- 快速图像分析
- 场景与主体识别
- 表情和模式专项分析
- 相似分组和组内比较
- 故事线与多样性选择
- 综合评分和原因生成
- 复核结果准备

界面应显示当前阶段、已完成数量、总数量和动态预计剩余时间。不得使用与真实处理量无关的
模拟进度。

## 15. 准确率验收

准确率必须按照摄影工作流指标验收：

- 摄影师最终精选照片召回率
- 好片被误判为淘汰建议的比例
- 人工需要查看的照片减少比例
- 相似组第一推荐命中率
- 群像闭眼和表情问题检出率
- 故事线关键场景和关键人物覆盖率
- 各模式独立指标

目前暂无真实样片，因此当前阶段可以完成产品、工程和自动化验证，但不能宣称选图准确率已经
达到生产标准。

后续评测集建议覆盖全部模式，每种模式至少 200 至 500 张，并由摄影师提供最终精选、淘汰、
相似组最佳和关键故事照片作为金标准。

稳定发布门槛冻结为：

| 指标                                        | 门槛                            |
| ------------------------------------------- | ------------------------------- |
| 摄影师最终保留图进入“精选 + 待确认”的召回率 | 不低于 99%                      |
| 最终保留图误入“淘汰建议”                    | 不高于 1%                       |
| 受保护拍摄组合召回率                        | 不低于 99%                      |
| 相似组最佳进入前三推荐                      | 不低于 90%                      |
| 达到有效像素门槛的人脸闭眼检测 F1           | 不低于 0.90，并分人群报告       |
| 关键人物和关键事件覆盖率                    | 不低于 95%                      |
| 1000 张中端设备端到端时间                   | 不超过 5 分钟；2 分钟为优化目标 |
| 取消响应                                    | 2 秒内停止新增重任务            |

比例指标必须按完整 shoot bootstrap 给出 95% 置信区间，并分别报告九种模式、设备、格式、人像
覆盖分层和冷/热缓存。任一安全指标未达标时功能保持实验状态，不得通过调整文案规避门槛。

## 16. V1 退役与数据策略

- 删除现有智能选图 V1 的前后端业务实现，不在其上继续增量修补
- 删除 V1 专用命令、事件、状态、预设和任务历史接入
- 删除 V1 技术文档、需求文档和已被当前基线吸收的讨论稿，避免成为并行事实源
- 不自动删除用户已经下载的模型文件
- 每张照片只保留一个最新已确认智能结果；第一次确认 V2 结果时覆盖旧智能结果
- V1 旧结果在首次 V2 确认前只作为旧数据保留，不参与 V2 评分和筛选

## 17. 非目标

- 不删除照片
- 不替代摄影师的最终审美决策
- 不把人工星级与 AI 星级混为同一来源
- 不评价人物是否正常或是否具有吸引力
- 不在低可信度时强制给出淘汰结论
- 不要求联网或上传照片
- 不维护多次智能选图任务历史
- 不生成 PDF 报告
- 不自动设置颜色标签或用户标签

## 18. 下一阶段

技术选型、架构边界和发布门槛见 `docs/smart-culling-v2-technical-architecture.md`，逐项实施顺序见
`docs/smart-culling-v2-implementation-plan.md`。下一阶段必须先完成 Phase 0 模型权利链、模型契约、
表情等价性、运行时兼容和初步性能验证；验证通过后才能替换 V1 业务实现并进入完整产品开发。
