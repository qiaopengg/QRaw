## 1. 执行规则

1. 本清单是唯一实施顺序，不从旧文档、V1 代码或历史 Q&A 恢复功能。
2. 每个任务开始前读取其调用方、导出、测试和同类实现；优先复用已有 feature slot、ORT、解码、缓存、EXIF 和 `featureData`。
3. 每个任务完成时同时提交实现、测试和验证记录；没有证据不得勾选。
4. 前一 Gate 未通过，不开始后一阶段。失败项保持未完成，不通过扩大范围或降低门槛绕过。
5. 新依赖、公共 API、数据迁移和上游接触点变化必须先解释并取得用户批准。
6. 用户选定 Product Design 方案前，不实施业务 UI；选定后把设计图作为 UI 验收基线。
7. 需求变化先改产品基线，再同步技术基线和本清单，最后改代码。

任务状态只使用：`[ ] 未开始`、`[~] 进行中`、`[x] 已验证`、`[!] 阻断`。

## 2. 所有权与上游隔离

### 2.1 本项目拥有并可维护

- `src/features/smart-culling/**`
- `src-tauri/src/features/smart_culling/**`
- `docs/smart-culling-v2-*.md`
- `docs/assets/smart-culling-v2-*`
- `tools/smart-culling/**`
- 智能选图模型转换、fixtures、benchmark 和模型包元数据目录
- `src/features/appFeatures.ts` 中现有智能选图注册行，但本次设计要求保持不变
- `src-tauri/src/features/mod.rs` 中智能选图 command 网关
- `src-tauri/src/lib.rs` 中经 `git blame` 证实由本项目加入的智能选图 command 行

### 2.2 默认禁止修改

- 上游 Library、Editor、Store、图片加载、RAW 解码、缓存、元数据和样式实现
- 上游作者拥有的 `src-tauri/src/lib.rs` 相邻行
- 上游 `rawler` fork 或 RAW 格式专用分支
- 上游 i18n 主资源；智能选图使用 feature-local 资源并复用现有 i18next
- `oldQRaw/**` 参考项目

若现有公开能力不足，先证明无法通过 feature slot/端口完成，再形成独立上游通用接口提案；未批准前
不得把智能选图条件分支写进上游组件。

### 2.3 固定接触面

- 前端继续由现有 `useSmartCullingFeature()` 注册，不再修改 `MainLibrary`、`LibraryView` 或 `LibraryHeader`。
- Rust 把现有多条本项目 V1 command 收敛为一条 `smart_culling_command`；收敛后不再扩展 `lib.rs`。
- 持久化只合并 `ImageMetadata.featureData.smartCullingV2`。
- 新模型只通过 Driver 输出 Evidence，不接触最终星级和侧车。

## 3. 里程碑与 Gate

| 里程碑 | 目标                             | Gate                                                  |
| ------ | -------------------------------- | ----------------------------------------------------- |
| M0     | 文档、许可证和视觉方案冻结       | G0: 三份文档一致，用户选定 UI 方案                    |
