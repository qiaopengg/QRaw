## 1. 执行纪律

1. 只以当前分支可读取、可执行、可复现的文件作为完成证据。
2. 内部检查点、历史 turn diff、未提交的其他工作树和文档自述都不能证明 Gate 通过。
3. 每项任务必须同时有实现、相关测试或检查命令和结果；没有证据保持未完成。
4. 前一 Gate 未通过，不启用依赖它的生产能力；不通过扩大范围或降低标准绕过。
5. 新依赖、共享公共 API、数据迁移和新的上游接触点必须先说明并取得用户批准。
6. V1 仅作为退役清单；不在旧评分、删除、直接 sidecar 写入或旧 UI 上继续修补。
7. 需求变化先更新产品基线，再同步技术、实施和 UI 文档，最后修改生产代码。

任务状态：`[ ] 未开始`、`[~] 进行中`、`[x] 已在当前分支验证`、`[!] 阻断`。

### 2.1 当前事实

- 当前任务起点：`06405ea2aaa22ebf87288bc0c88cef5c202d7b2a`。

- 所有权 baseline、V1 inventory、边界检查和退役检查已经在当前工作树建立并可执行。
- V2 业务代码位于前后端独立 feature 目录；宿主只保留一个 command 转发、一个 command 注册和必要状态清理。
- 当前实现已经形成安全可复核闭环，但不能据此推导 G2/G4：真实摄影效果、关键人物匹配、拍摄组合、

- `src/features/appFeatures.ts`：当前注册已经足够，保持不变。
- `src/features/contracts.ts`：当前 slot 已足够，保持不变。
- Library、Editor、Store、通用 hooks、主 i18n、RAW 解码、渲染和 sidecar 模块：默认保持不变。

### 3.3 允许收敛但不得扩张的混合所有权文件

- `src-tauri/src/features/mod.rs`：只保留一个智能选图网关转发。
- `src-tauri/src/lib.rs`：只把当前两个智能选图注册收敛为一个；不加入业务逻辑。
- `src-tauri/src/app_state.rs`：V2 自有协调器建立后移除 V1 人脸模型缓存；不新增智能选图业务状态。

这些文件只能修改 `git blame` 可证明由本项目二开加入的智能选图行。若现有端口不足，先形成最小
通用接口提案并取得批准，不得直接污染上游模块。
