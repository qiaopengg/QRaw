# 智能选图独立盲测流程

## 目的与边界

本流程用于回答一个严格问题：**当前人像模式算法在从未参与阈值调整的新照片上，与摄影师人工结果有多接近**。

- 旧的 `manual-reference`、`ai-run-v001`～`v003` 已参与分析和校准，只能作为训练/回归集，不能再宣称为盲测集。
- 盲测不会自动训练模型，也不会按文件名查答案；揭盲后只能形成评估报告。
- 如果根据本轮误差继续修改算法，这批照片从该时刻起转为训练/验证集；下一次可信盲测必须换一批未见照片。
- 当前盲测针对 macOS Debug 校准策略 `qraw-smart-culling-policy-4.9-macos-expression-incremental-calibration`。Release/其他构建策略仍为 `qraw-smart-culling-policy-4.2-safe-evidence`，不得用 Debug 盲测结果宣称 Release 能力已发布。
- 当前配对重放器固定使用 `portrait` 策略，不读取任务的其他模式或指定人物配置。它可以验证 4.9 的冻结眼态和人像表情组件，但不能验证 Face Capture Quality 在环境人像/自动有人策略中的业务准确率，也不能宣称群像、环境人像、风光或自动/混合模式已通过盲测。
- 已用于融合头训练/回归的 130 张表情素材、28 张生成校准素材、`e001` 的 10 张增量校准素材和旧 200 张回归素材都不是盲测集；即使按完整场景留出，也只能报告校准验证结果。`e002`、`e003` 和 `e004` 均已揭示人工答案，从揭示时起就是已知数据，不得再反称为未见数据。下一次前瞻验证必须使用全新 `e005` 或其他未见任务。

## 构建能力差异

- macOS Debug 只在隔离 FaceMesh/Blendshape/HSEmotion POC 资产完整且 Core ML 严格禁止 CPU 回退路径可用时，运行 `qraw-eye-model-contract-1.0` + `qraw-eye-policy-1.1` 眼态契约和 HSEmotion 融合表情头；眼态仍先独立完成，融合失败只能让表情不可用，不能改写眼态。表情低分同样进入固定权重组合，只有质量分不可用才人工复核。只读非眼表情序列仍要求指定人物身份已 confirmed，且 `stable` 不能代替已完成质量评估。
- Release/非 macOS Debug 明确将眼态和表情 POC 记为 unavailable，不得静默借用 Debug 结果或回退到未验证推断。
- ARNIQA 与构图模型均未进入任何生产策略：ARNIQA 只是本地隔离 POC，构图证据仍未生产化。证据缺失必须体现在保守分数区间和人工复核中，不得伪装为已完成评分。
- 每份冻结快照必须保留完整 `policyVersion` 和 `modelVersion`；比较报告只能比较同一构建契约的结果。

## 数据隔离

开始前准备两个彼此隔离的位置：

```text
<blind-root>/
  source/                 # 纯净原图，无 rrdata
  ai-run-v001/            # 从 source 复制，供程序智能选图

<manual-holdout>/         # 人工先独立打星，但冻结前不得复制到 blind-root
```

约束：

1. `source`、`ai-run-v001`、后续揭示的 `manual-reference` 文件名和图片字节必须完全一致。
2. 人工打星应在不查看本轮 AI 结果的情况下完成；人工目录在冻结前由用户保管，不向算法或评测进程提供路径。
3. `blind-root` 必须是一批此前未用于讨论、调参或代码验证的新照片。
4. 0 星表示待人工/无确定真值，统计准确率时排除；1 ～ 5 星沿用已确认的人工语义。

## 阶段 A：运行 AI 并冻结结果

先重新启动当前 Debug 版本，在 `ai-run-v001` 中以**人像模式**完成一次智能选图。确认任务完整结束后，先进入 `src-tauri` 目录，以便自动采用该目录的 `rust-toolchain.toml`，然后执行：

```bash
QRAW_PAIRED_CULLING_EVAL_ROOT="/绝对路径/blind-root" \
QRAW_PAIRED_CULLING_EVAL_AI_RUN="ai-run-v001" \
QRAW_BLIND_CULLING_SNAPSHOT_OUTPUT="/绝对路径/blind-ai-v001.snapshot.json" \
ORT_DYLIB_PATH="$PWD/resources/libonnxruntime.dylib" \
cargo test --lib \
  features::smart_culling::face_motion_poc::paired_eval::freeze_blind_ai_snapshot \
  -- --ignored --exact --nocapture
```

冻结命令会拒绝以下情况：

- `blind-root/manual-reference` 已经存在；
- `source` 含 `.rrdata`，或两份图片名称/字节不一致；
- AI 侧车不是 `source=ai`，或模型/策略版本不匹配；
- 没有任何可认证的 AI 侧车；
- 快照输出文件已经存在。

成功后终端会输出：

```text
QRAW_BLIND_CULLING_SNAPSHOT_SHA256=<64 位哈希>
```

把快照文件和这段 SHA-256 单独保存。不要编辑快照，也不要重新运行或修改 `ai-run-v001`。

如果人工标签针对**表情组件**，此时仍不得创建 `manual-reference`，还必须冻结人工揭示前的表情连续分：

```bash
QRAW_PAIRED_CULLING_EVAL_ROOT="/绝对路径/blind-root" \
QRAW_PAIRED_CULLING_EVAL_AI_RUN="ai-run-v001" \
QRAW_PAIRED_CULLING_EVAL_OUTPUT="/绝对路径/blind-expression-predictions-v001.jsonl" \
QRAW_BLIND_CULLING_SNAPSHOT="/绝对路径/blind-ai-v001.snapshot.json" \
QRAW_BLIND_CULLING_SNAPSHOT_SHA256="<上一步记录的 64 位哈希>" \
ORT_DYLIB_PATH="$PWD/resources/libonnxruntime.dylib" \
cargo test --lib \
  features::smart_culling::face_motion_poc::paired_eval::freeze_blind_expression_predictions \
  -- --ignored --exact --nocapture
```

成功后会输出 `QRAW_BLIND_EXPRESSION_PREDICTIONS_SHA256=<64 位哈希>`。该不可覆盖 JSONL 固定每张原图的哈希、完整模型/策略契约和表情组件预测；其中人工星级必须全部为 0，冻结器发现 `manual-reference` 或任何人工答案都会拒绝执行。文件及其 SHA-256 必须与 AI 快照一并保存。

## 阶段 B：揭示人工答案并评测

只有阶段 A 成功后，才将人工目录复制为：

```text
<blind-root>/manual-reference/
```

然后执行严格揭盲：

```bash
QRAW_PAIRED_CULLING_EVAL_ROOT="/绝对路径/blind-root" \
QRAW_PAIRED_CULLING_EVAL_AI_RUN="ai-run-v001" \
QRAW_PAIRED_CULLING_EVAL_OUTPUT="/绝对路径/blind-evaluation.jsonl" \
QRAW_BLIND_CULLING_SNAPSHOT="/绝对路径/blind-ai-v001.snapshot.json" \
QRAW_BLIND_CULLING_SNAPSHOT_SHA256="<阶段 A 记录的 64 位哈希>" \
ORT_DYLIB_PATH="$PWD/resources/libonnxruntime.dylib" \
cargo test --lib \
  features::smart_culling::face_motion_poc::paired_eval::blind_manual_ai_reveal \
  -- --ignored --exact --nocapture
```

如果人工星标只针对表情组件，请直接使用下面的完整命令替代上面的通用命令：

```bash
QRAW_PAIRED_CULLING_EVAL_MANUAL_TARGET="expression" \
QRAW_PAIRED_CULLING_EVAL_ROOT="/绝对路径/blind-root" \
QRAW_PAIRED_CULLING_EVAL_AI_RUN="ai-run-v001" \
QRAW_PAIRED_CULLING_EVAL_OUTPUT="/绝对路径/blind-expression-evaluation-v001.jsonl" \
QRAW_BLIND_CULLING_SNAPSHOT="/绝对路径/blind-ai-v001.snapshot.json" \
QRAW_BLIND_CULLING_SNAPSHOT_SHA256="<阶段 A 记录的 AI 快照哈希>" \
QRAW_BLIND_EXPRESSION_PREDICTIONS="/绝对路径/blind-expression-predictions-v001.jsonl" \
QRAW_BLIND_EXPRESSION_PREDICTIONS_SHA256="<阶段 A 记录的表情预测哈希>" \
ORT_DYLIB_PATH="$PWD/resources/libonnxruntime.dylib" \
cargo test --lib \
  features::smart_culling::face_motion_poc::paired_eval::blind_manual_ai_reveal \
  -- --ignored --exact --nocapture
```

评测进程会在读取人工星标前先验证：

- 快照文件 SHA-256 未变；
- AI 运行目录、策略版本、模型版本未变；
- 每张原图及 AI 副本字节未变；
- 每个已有 AI 侧车的完整文件字节未变；
- 最终综合星级标签：当前代码重放结果必须与冻结的 AI 星标一致；
- 表情专项标签：在读取人工星标前验证预冻结预测文件的 SHA-256、逐图原图哈希、模型/策略契约和“人工仍为 0”状态，指标直接使用冻结连续分。当前最终星级重放若与应用侧车不同，会单独报告为运行路径漂移，不能覆盖冻结预测。

成功时会生成逐图 JSONL，并先分别输出：实际存在 AI 侧车的覆盖率、当前代码自动决定覆盖率、当前人工复核覆盖率。精确星级命中率、误差不超过 1 星比例、平均绝对误差（MAE）和“可用/不可用”二分类一致率只在对应的**已有侧车/已自动决定且人工非 0 星**子集上计算；缺失侧车和复核项绝不再当作 0 星。报告结论必须同时附带分母和覆盖率，禁止只报告子集准确率。严格模式使用不可覆盖输出；任何校验失败都不会留下一个可被误认作成功报告的目标文件。

## 表情组件校准回放（不是盲测）

如果人工星标只表达表情好坏，而不是最终综合星级，必须显式增加：

```bash
QRAW_PAIRED_CULLING_EVAL_MANUAL_TARGET="expression" \
QRAW_PAIRED_CULLING_EVAL_ROOT="/绝对路径/expression-calibration-root" \
QRAW_PAIRED_CULLING_EVAL_AI_RUN="ai-run-v001" \
QRAW_PAIRED_CULLING_EVAL_OUTPUT="/绝对路径/expression-evaluation.jsonl" \
ORT_DYLIB_PATH="$PWD/resources/libonnxruntime.dylib" \
cargo test --lib \
  features::smart_culling::face_motion_poc::paired_eval::paired_manual_ai_replay \
  -- --ignored --exact --nocapture
```

该模式把人工 3 ～ 5 星解释为表情“可用”，1 ～ 2 星解释为表情“不可用”，0 星排除；质量分 `>= 0.5` 仅用于组件通过/不通过诊断，同时报告可评分覆盖率、归一化质量 MAE 和未知数量，并明确跳过最终 1 ～ 5 星一致率。质量分低于 0.5 仍会进入正常综合权重，不能解释为流程失败；不要用最终组合星级与表情专属星标计算精确命中率。

## 结果使用规则

- 先完整保存盲测报告，再查看错例；不得边揭示边调阈值。
- 眼睛、遮挡、姿态、表情、模糊和曝光最好另做独立属性标注，不能仅靠最终星级反推单一缺陷。
- 数据应覆盖眼镜、半闭眼/眨眼、单眼闭合、侧脸、遮挡、小脸、多人、弱光、连拍和有意闭目姿态。
- 4 星与 5 星需要足量样本；若某档样本极少，只能报告观察结果，不能据此冻结阈值。
- SHA-256 是过程完整性校验，不是对恶意修改者的身份认证；可信度仍依赖用户确实隔离人工目录并记录原始哈希。
