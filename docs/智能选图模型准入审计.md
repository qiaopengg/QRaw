# 智能选图模型准入审计

> 审计日期：2026-08-19
> 状态：候选模型官方源静态审计；不代表已批准生产接入
> 范围：ARNIQA、Efficient-FIQA、SAMP-Net、ReLIC、MediaPipe FaceMeshV2 / BlendshapeV2
> 项目约束：必须同时遵守根目录 `AGENTS.md` 与
> `docs/feature-integration-guidelines.md`

## 1. 文档目的与结论边界

本文只记录能够从候选模型的官方仓库、官方论文、官方模型卡或官方权重托管页核实的事实，以及基于
公开计算图作出的明确技术推断。文中的“ONNX 可行性”“Core ML 风险”“DirectML 风险”均为静态审阅
结论，不是运行验证结果。

必须始终区分三类授权对象：

1. 源代码许可证；
2. 模型权重的使用和再分发许可；
3. 训练数据、标注和衍生权重的使用限制。

**代码许可证不等于权重或训练数据的商业使用、转换和再分发许可。** 仓库标注 Apache-2.0 或 MIT，
只能证明其明确覆盖的仓库内容采用该许可证，不能自动证明第三方训练图片、独立托管的 checkpoint、
转换后的 ONNX 或其衍生权重可以随商业应用分发。

本轮因执行环境的外部下载额度和网络策略拦截，没有实际下载任何新增候选权重。因此本轮没有取得或
验证：

- 候选资产的本地精确字节数；
- 下载文件的 SHA-256；
- PyTorch / TFLite 官方参考输出；
- ONNX 导出结果及数值一致性；
- ONNX Runtime 会话创建与完整图接管；
- macOS Core ML 和 Windows DirectML 的真实推理、性能、内存或回退行为。

官方页面显示的大小会在本文中注明为“官方页面报告值”，不得当作本地文件验证值。没有完成上述项目
前，本文中的候选最多只能获得“隔离 POC”资格，不能进入应用生产资源或自动写星链路。

## 2. 审计结果摘要

| 候选 | 目标能力 | 静态准入结论 | 主要原因 |
| --- | --- | --- | --- |
| MediaPipe FaceMeshV2 / BlendshapeV2 | 眼睛原始证据、表情动作特征 | 保留当前固定版本；表情阶段不新增模型 | 官方模型卡为 Apache-2.0，项目已有工程 POC；52维动作系数不是照片表情可用性结论 |
| ARNIQA | 全图光学质量、全图/人物区域质量辅助 | 条件准入隔离 POC，优先级第一 | 标准 ResNet 计算图，官方发布权重；权重和训练数据再分发许可仍需确认 |
| Efficient-FIQA | 人物/人脸感知质量辅助 | 暂缓；仅当 ARNIQA 人物区域证据不足时研究 | 模型轻量，但训练数据包含 CelebA、Flickr 和约40万张互联网人脸，权重无独立商业许可说明 |
| SAMP-Net | 构图质量 | 条件准入研究 POC，不得直接生产化 | 构图语义明确，但 checkpoint 较大、输入会拉伸宽高比，权重和数据许可不清晰 |
| ReLIC | 构图/审美备用基线 | 当前不准入首轮 POC | 无正式 Release、权重直链/大小/哈希和推理契约说明不足，旧计算图导出风险较高 |

当前建议的最小新增模型数量是两个：

1. ARNIQA 同时试验全图和人物区域；
2. 一个最终通过授权、导出和盲测门禁的构图模型。

只有 ARNIQA 人物区域证据无法满足人物清晰度门禁时，才继续评估 Efficient-FIQA。表情第一阶段直接
复用已固定的 MediaPipe 原始证据，不下载新的情绪或动作模型。

## 3. ARNIQA

### 3.1 官方来源

- [官方仓库](https://github.com/miccunifi/ARNIQA)
- [官方权重 Release](https://github.com/miccunifi/ARNIQA/releases/tag/weights)
- [官方 `hubconf.py`](https://github.com/miccunifi/ARNIQA/blob/main/hubconf.py)
- [官方 ResNet 实现](https://github.com/miccunifi/ARNIQA/blob/main/models/resnet.py)
- [官方配置](https://github.com/miccunifi/ARNIQA/blob/main/config.yaml)
- [官方论文](https://arxiv.org/abs/2310.14918)

官方 `hubconf.py` 声明的权重地址前缀为：

```text
https://github.com/miccunifi/ARNIQA/releases/download/weights
```

主要文件包括：

```text
ARNIQA.pth
regressor_live.pth
regressor_csiq.pth
regressor_tid2013.pth
regressor_kadid10k.pth
regressor_flive.pth
regressor_spaq.pth
regressor_clive.pth
regressor_koniq10k.pth
```

例如官方代码实际使用的下载地址可以由上述前缀与文件名直接拼接。Release 页面没有发布这些文件的
SHA-256。

### 3.2 代码、权重和训练数据许可

已核实事实：

- 官方仓库标注 Apache License 2.0；
- 预训练 encoder 和多个数据集回归头由官方 GitHub Release 提供；
- encoder 的训练依赖 KADIS-700 数据，回归头分别依赖 LIVE、CSIQ、TID2013、KADID-10K、FLIVE、
  SPAQ、CLIVE 或 KonIQ-10K 等数据集。

风险判断：

- 官方仓库没有在模型卡中逐项声明 Release 权重的独立再分发许可证；
- 官方仓库没有汇总证明上述训练数据都允许衍生权重随商业桌面应用再分发；
- 因此 Apache-2.0 仓库许可不足以单独完成生产准入。

准入前必须进一步确认权重再分发权、所选回归头对应数据集的条款、署名与第三方通知要求。

### 3.3 输入、输出和模型规模

已核实事实：

- encoder 为 ResNet-50；
- 输入为 ImageNet 均值和标准差归一化后的 RGB 图像；
- 同一图像需要全尺度和半尺度两路输入，两路共享 encoder；
- 官方配置的训练 patch 和测试 crop 为 `224 × 224`；
- 官方论文流程对中心和四角 crop 的结果取平均；
- 两路特征拼接后由线性回归头输出质量分；
- 官方推理接口可以将结果缩放到 `[0, 1]`，数值越高表示质量越好；
- 回归头可以选择不同 IQA 数据集，数据集对应的 MOS/DMOS 方向由官方代码统一转换。

明确推断：

- 按官方 ResNet-50 去掉 ImageNet 分类层的结构推导，实际质量特征主干约为 23.51M 参数；
- FP32 纯主干参数理论大小约为 94MB，未包含容器元数据和 checkpoint 中可能保留的训练结构；
- 官方 `ResNet` 类还定义了投影头，但 ARNIQA 质量回归使用的是主干特征。正式导出时可以研究剥离
  不参与质量输出的投影头，但必须先完成官方 checkpoint 与精简图的逐输出数值对照。

以上参数量和理论大小是根据官方源码推导，不是本轮下载后的文件测量值。

### 3.4 ONNX、Core ML 与 DirectML 风险

静态审阅结论：ONNX 导出可行性较高。

主要计算由卷积、BatchNorm、ReLU、池化、L2 归一化、拼接和线性层组成。建议把缩放、五区域裁切、
ImageNet 归一化和多 crop 聚合保留在智能选图独立 feature 内，由应用侧完成；ONNX 固定为明确的
`1 × 3 × 224 × 224` 主干输入和单一回归输出。

主要风险不是罕见算子，而是：

- 同一图像需要多 crop、双尺度推理，批量照片下计算量和显存占用较高；
- 不同回归头在真实专业相机照片上的分布可能不同；
- Core ML 或 DirectML 能创建会话，不等于完整图没有回落到默认 CPU EP；
- 精简投影头、合并回归头或量化都会改变生产资产，必须重新做数值一致性和完整图接管验证。

本轮没有生成 ONNX，也没有完成 Core ML 或 DirectML 运行验证。

### 3.5 业务适用性和准入结论

ARNIQA 输出的是无参考综合画质，不是专门的“明确失焦”三分类器。它可以作为曝光、噪声、压缩、
模糊和综合失真证据，但不得单独触发“明确不清晰直接1星”。第一层清晰度门禁仍应组合：

- 现有多区域、多尺度锐度证据；
- ARNIQA 全图或主体区域分数；
- 主体有效像素、置信度和明确原因；
- 在冻结样片上标定的高置信阈值。

为减少模型数量，可以先用同一个 ARNIQA encoder 分别评估全图和人物区域。该做法是待盲测的工程
推断，不代表通用 IQA 模型已经具备可靠人脸可用性判断。

准入结论：**优先进入隔离 POC；未完成权重许可、SHA、ONNX 数值对齐和双平台验证前不得打包。**
第一轮建议同时比较 SPAQ、KonIQ-10K 与 KADID-10K 回归头，不能未经样片验证直接沿用默认回归头。

## 4. Efficient-FIQA

### 4.1 官方来源

- [官方仓库](https://github.com/sunwei925/Efficient-FIQA)
- [官方论文](https://arxiv.org/abs/2507.15709)
- [官方论文 HTML](https://arxiv.org/html/2507.15709v2)
- [官方学生模型 checkpoint](https://github.com/sunwei925/Efficient-FIQA/blob/main/ckpts/EdgeNeXt_XXS_checkpoint.pt)
- [官方测试代码](https://github.com/sunwei925/Efficient-FIQA/blob/main/test.py)
- [官方模型定义](https://github.com/sunwei925/Efficient-FIQA/blob/main/models/FIQA_model.py)

### 4.2 代码、权重和训练数据许可

已核实事实：

- 官方仓库标注 Apache License 2.0；
- 学生模型 checkpoint 直接存放在该仓库中，GitHub 页面报告大小为 4.55MB；
- 官方论文说明标注训练集包含 27,686 张来自 CelebA 和 Flickr 的人脸图像；
- 官方论文说明另外从互联网收集约 400,000 张未标注人脸用于两轮伪标签训练；
- 官方 README 明确说明原始未标注图片因版权限制无法提供。

风险判断：

- 仓库没有为 checkpoint 提供独立的模型许可证、模型卡或商业再分发声明；
- CelebA、Flickr 图片和约40万张互联网图片的来源条款不能由仓库 Apache-2.0 代替；
- 该风险不等价于判定权重必然不可用，但足以阻止未经法律确认的生产打包。

### 4.3 输入、输出和模型规模

已核实事实：

- 学生模型使用 EdgeNeXt-XX-Small 主干和两层质量回归 MLP；
- 官方测试预处理把 RGB 图像短边缩放后进行 `352 × 352` 中心裁切，并使用 ImageNet 归一化；
- 模型输出一个质量标量；官方实现没有在输出端使用 sigmoid 或 clamp；
- 官方论文报告学生模型为约 1.180M 参数、`352 × 352` 下约 0.4949 GFLOPs；
- 官方 GitHub 页面报告 checkpoint 为 4.55MB。

4.55MB 是官方页面报告值，本轮没有下载文件，因此没有取得本地精确字节数和 SHA-256。

### 4.4 ONNX、Core ML 与 DirectML 风险

静态审阅结论：固定输入尺寸后，ONNX 导出具有中高可行性，但风险高于 ARNIQA。

EdgeNeXt 除卷积和池化外还包含分组卷积、LayerNorm、张量转置和注意力相关路径。预计可以使用现代
ONNX opset 表达，但不能据此断言项目当前 ONNX Runtime 版本、Core ML EP 或 DirectML EP 会完整接管。

准入 POC 必须至少验证：

- 固定 `1 × 3 × 352 × 352` 输入；
- PyTorch 与 ONNX 的逐样片数值误差；
- Core ML 和 DirectML 严格禁用默认 CPU 回退时的会话创建及真实推理；
- 每个节点的 EP 分配、冷启动、热推理、内存和批量吞吐；
- 336 与352输入的效果/性能取舍不能只引用论文数据。

本轮没有执行上述验证。

### 4.5 业务适用性和准入结论

官方论文将任务定义为“感知人脸质量”，不是只判断人物是否对焦。其标量可能同时响应曝光、姿态、
退化和其他人脸感知因素。它只能作为人物清晰度/可用性的一个证据，未经误杀率标定不能执行第一层
硬门禁。

准入结论：**暂缓生产准入。先用 ARNIQA 人物区域、现有高分辨率人脸锐度及 FaceMesh 可见性证据完成
盲测；只有该组合仍不足，并且 Efficient-FIQA 的权重和训练数据风险获得明确处理后，才进入隔离 POC。**

## 5. SAMP-Net

### 5.1 官方来源

- [官方仓库（CADB 与 SAMP-Net）](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB)
- [官方论文](https://arxiv.org/abs/2104.03133)
- [官方 SAMP-Net 模型代码](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB/blob/main/SAMPNet/samp_net.py)
- [官方输入和显著图代码](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB/blob/main/SAMPNet/cadb_dataset.py)
- [官方配置](https://github.com/bcmi/Image-Composition-Assessment-Dataset-CADB/blob/main/SAMPNet/config.py)
- [官方 Dropbox checkpoint](https://www.dropbox.com/scl/fi/k1yuyhotuk9ky3m41iobg/samp_net.pth?dl=0&rlkey=aoqqxv27wd5qqj3pytxki6vi3&st=0ffubx5d)

旧仓库 URL `bcmi/Image-Composition-Assessment-with-SAMP` 当前会重定向到上述 CADB 仓库。官方 README
还提供百度网盘下载，访问码为 `5qgg`。

### 5.2 代码、权重和训练数据许可

已核实事实：

- 官方仓库标注 MIT License；
- 官方 README 报告 `samp_net.pth` 约为 180MB；
- checkpoint 通过独立 Dropbox / 百度网盘提供，没有 GitHub Release 和公开 SHA-256；
- CADB 包含 9,497 张图，每张由5位具有美术背景的评分者给出1至5分构图评分；
- CADB 建立在 AADB 图像和属性基础上，并增加构图评分、场景、构图类别与构图元素标注。

风险判断：

- 仓库 MIT 许可不能自动证明 AADB/CADB 图像、标注和 Dropbox checkpoint 的商业再分发权；
- checkpoint 没有独立模型卡、权重许可证、校验值或固定 Release；
- 180MB 是官方 README 近似报告值，不是本轮本地测量值。

### 5.3 输入、输出和模型规模

已核实事实：

- 默认主干为 ResNet-18；
- 输入一为 ImageNet 归一化的 `3 × 224 × 224` RGB 图；
- 输入二为 `1 × 224 × 224` 光谱残差显著图；
- 显著图由官方数据代码使用灰度图、FFT、频谱残差、逆 FFT、GaussianBlur 和分位数归一化生成；
- 默认使用8种 multi-pattern；
- 输出包括8维 pattern 权重、6维构图属性和5档构图评分分布；
- 评分分布与 `[1, 2, 3, 4, 5]` 加权求和后得到构图均值分。

官方没有报告完整 SAMP/AAFF 图的准确参数量。不能只按 ResNet-18 的规模估算最终模型，因为额外的
多模式池化、属性融合和评分头也包含参数。checkpoint 约180MB的报告值还可能包含训练容器开销，必须
实际下载并剥离训练状态后才能确认纯推理权重和 ONNX 大小。

### 5.4 ONNX、Core ML 与 DirectML 风险

静态审阅结论：模型主体 ONNX 可行性中等，完整预处理部署风险中高。

固定 `224 × 224` 后，主干卷积、模式池化、切片、拼接、线性层和 Softmax 原则上可以映射到 ONNX。
但光谱残差显著图依赖 FFT，不应假设 Core ML 或 DirectML 能在同一 ONNX 图中稳定接管。更可控的方式是
在智能选图 feature 内用固定、可回归的 CPU 预处理生成显著图，再把两个张量送入 ONNX。

另一个高风险事实是：官方数据代码使用 `Resize((224, 224))`，会把任意横竖比图像直接拉伸成正方形。
构图任务对几何比例敏感；原样复现会改变照片几何，改成等比 letterbox 又会偏离训练分布。横幅、竖幅、
方幅必须分别进入真实盲测，不能仅凭 CADB 指标决定生产准入。

本轮没有导出模型，也没有运行 Core ML 或 DirectML。

### 5.5 业务适用性和准入结论

SAMP-Net 的评分目标与“照片构图质量”直接相关，并提供 pattern 权重和属性输出，语义上比通用画质
模型更接近当前需求。但其数据规模、宽高比处理、资产体积和再分发许可都构成发布风险。

准入结论：**完成权重和数据许可确认后，可以进入隔离研究 POC；在宽高比盲测、ONNX 数值对齐和双平台
完整图验证通过前，不进入应用资源。**

## 6. ReLIC

### 6.1 官方来源

- [官方仓库](https://github.com/fei-aiart/ReLIC)
- [官方论文页面](https://www.sciencedirect.com/science/article/pii/S1077314220300801)

论文原地址使用 `fei-hdu/ReLIC`，当前会重定向到 `fei-aiart/ReLIC`。

### 6.2 代码、权重和训练数据许可

已核实事实：

- 官方仓库标注 MIT License；
- 官方 README 声明 AVA、CPC、JAS_composition 和 JAS_aesthetic 四套实现；
- README 声明预训练模型位于各实现的 `pretrain_model` 目录；
- 仓库没有发布 GitHub Release；
- README 没有列出稳定的权重直链、权重大小、SHA-256 或独立模型许可证；
- 权重分别依赖 AVA、CPC 和 JAS 数据。

风险判断：

- MIT 代码许可不能替代 AVA、CPC、JAS 数据和衍生 checkpoint 的许可；
- 缺少稳定权重发布、哈希和模型卡，使供应链复现与审计弱于其他候选。

### 6.3 输入、输出和模型规模

已核实事实：

- 官方论文使用 CNN 深层特征构建全连接图，以不同位置特征间的相似度表示构图；
- 图的全局属性表示其他审美因素，再通过 gate 合成预测；
- 官方仓库将 MobileNetV2 标为主要技术主题；
- 不同目录分别执行 AVA 审美、CPC 构图、JAS 构图和 JAS 审美预测。

官方 README 没有形成稳定的推理契约，未明确统一输入尺寸、输出张量、分数范围、各 checkpoint 文件名
和大小。本轮没有下载仓库权重，不能用猜测补齐这些信息。

### 6.4 ONNX、Core ML 与 DirectML 风险

静态审阅结论：ONNX 可行性为中低，风险高于 SAMP-Net。

MobileNetV2 主干本身容易导出，但全连接图涉及空间特征重排、两两相似度矩阵、批量矩阵运算和 gate。
旧版 PyTorch 实现还可能把图规模或 reshape 写入 Python 控制流。只有固定输入后实际导出，才能判断
ONNX 是否保留等价计算，以及 Core ML / DirectML 是否完整接管矩阵和归一化路径。

本轮没有取得 checkpoint、生成 ONNX 或运行任一平台。

### 6.5 业务适用性和准入结论

ReLIC 可以作为轻量构图思路的备用基线，但其供应链、推理契约和部署材料明显不完整。它不应与
SAMP-Net 同时进入首轮，避免为尚未证明的候选增加重复模型和转换成本。

准入结论：**当前不进入首轮下载和 POC；只有 SAMP-Net 因效果、性能或授权失败时，才重新审计 ReLIC
的具体 checkpoint 和运行代码。**

## 7. MediaPipe FaceMeshV2 与 BlendshapeV2

### 7.1 官方来源

- [MediaPipe 官方仓库](https://github.com/google-ai-edge/mediapipe)
- [Face Landmarker 官方说明](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker)
- [FaceMeshV2 官方模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Face%20Mesh%20V2.pdf)
- [BlendshapeV2 官方模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Blendshape%20V2.pdf)
- [官方52维枚举定义](https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/vision/face_landmarker.py)

### 7.2 代码和模型许可

已核实事实：

- MediaPipe 官方仓库标注 Apache License 2.0；
- FaceMeshV2 与 BlendshapeV2 官方模型卡都明确标注 Apache License 2.0；
- 项目现有文档已经记录这两个模型的隔离 POC、固定资产哈希和 macOS Core ML 工程验证状态；
- 本轮没有重新下载或重新验证这些既有资产。

### 7.3 输入和输出

FaceMeshV2 官方模型卡说明：

- 输入为带约25%边距并缩放到 `256 × 256` 的人脸 RGB 图；
- 输出478个三维人脸关键点和 face presence；
- 模型设计目标是单目、前置手机相机视频中的实时人脸表面估计。

BlendshapeV2 官方模型卡说明：

- 输入为 FaceMesh 478点中的146个关键点；
- 输入张量语义为每个关键点的二维坐标；
- 输出52个 `[0, 1]` 浮点动作系数；
- 系数覆盖眉、脸颊、眼睛、下颌、嘴和鼻等动作；
- 模型主要目标是实时控制三维头像，而不是评价照片表情是否适合成片。

### 7.4 是否足以支持表情状态

已核实事实是：52维输出提供可解释的当前面部动作证据，但不输出“稳定可用”“说话过渡”“异常瞬间”
或“摄影成片可用性”标签。

明确推断：第一版表情模块不需要下载新的通用情绪模型，可以使用以下只读特征训练很小的 QRaw 业务
分类头：

- 嘴部、下颌、眉、脸颊和鼻部动作；
- 左右对称差；
- face presence、头部姿态和关键点一致性；
- 同一相似组、同一人物的相邻帧变化。

单张照片不能可靠证明表情正在形成或结束；“过渡”结论必须优先依赖同人物连拍上下文。没有足够序列
证据时应输出 `unknown`，而不是用通用情绪类别代替。

### 7.5 锁定睁闭眼核心的准入边界

后续表情能力必须服从以下隔离规则：

1. 眼睛模块继续固定当前 FaceMeshV2、BlendshapeV2 资产哈希、ROI、坐标投影和 EyeAssessment 策略版本；
2. 表情模块只能读取固定版本的原始证据，不得修改眼睛结果；
3. 表情第一版特征白名单排除 `eyeBlink*`、`eyeLook*`、`eyeSquint*` 和 `eyeWide*`，避免重复评分或以
   表情逻辑覆盖眼睛硬门禁；
4. 如果表情需要更换 FaceMesh、Blendshape 或引入新面部动作模型，必须使用独立资产和独立版本，不能
   原地替换眼睛使用的模型；
5. 任何共享原始模型的变更都必须重新运行冻结眼睛回归集，并要求逐图 EyeAssessment 零变化；
6. 表情、光学质量和构图高分都不能突破眼睛不可用或有意闭目所产生的最终星级上限。

准入结论：**继续使用当前固定版本；表情第一阶段不下载新模型，只允许建立与眼睛隔离的小型业务
分类头和盲测流程。**

## 8. 模型复用与数量控制

### 8.1 可以复用的计算

- MediaPipe 的一次 FaceMesh/Blendshape 原始推理可以同时给眼睛和表情提供只读证据；两个业务模块仍需
  独立策略、版本和测试；
- ARNIQA 可以在隔离 POC 中复用同一 encoder 分别分析全图和人物区域；
- 现有人脸检测、FaceMesh presence、姿态、有效像素和多尺度锐度可以与 ARNIQA 人物区域结果合成
  人物清晰度门禁，先验证能否省去 Efficient-FIQA。

### 8.2 不能合并的语义

- ARNIQA 是失真/综合画质证据，不能替代构图模型；
- SAMP-Net 的构图属性或景深属性不能替代光学质量；
- Efficient-FIQA 的感知人脸质量不能直接替代明确失焦硬门禁；
- MediaPipe Blendshape 动作系数不能直接替代表情成片可用性；
- 任何单个公共模型都不能绕过 QRaw 的模式权重、人工审核和最终硬门禁。

## 9. 推荐下载和验证顺序

### 第一步：不下载新表情模型

冻结现有 FaceMeshV2 / BlendshapeV2 资产、EyeAssessment 输出和逐图回归基线。后续表情 POC 只读取固定
原始证据。

### 第二步：ARNIQA

在外部下载额度恢复后，只下载一次官方 encoder，并优先取得 SPAQ、KonIQ-10K、KADID-10K 三个很小的
回归头用于对照。下载后立即记录：

- 最终重定向后的来源 URL；
- GitHub tag / commit；
- 精确字节数；
- SHA-256；
- 许可证和第三方通知快照。

先完成全图与人物区域盲测，再决定是否需要 Efficient-FIQA。

### 第三步：构图候选

先完成 SAMP-Net checkpoint 和 CADB/AADB 权利审查。只有许可风险可接受时，才下载 SAMP-Net 做横幅、
竖幅和方幅隔离 POC。ReLIC 不与其并行引入；SAMP-Net 明确失败后再重新审计 ReLIC。

### 第四步：可选 Efficient-FIQA

只有 ARNIQA 人物区域加现有确定性证据仍不能达到人物清晰度门禁目标，并且权重/训练数据风险获得明确
处理后，才下载 4.55MB 官方页面所示的学生 checkpoint。

## 10. 所有候选统一准入门禁

每个新增候选都必须单独满足以下条件，不能由另一个模型的验证结果代替：

1. 固定官方仓库、tag/commit、下载 URL、精确字节数和 SHA-256；
2. 分别确认代码、权重、训练数据、转换权和再分发许可；
3. 保存官方框架参考输出，不使用文件名、目录名或人工答案参与推理；
4. 导出静态 ONNX，并验证全部输出的最大/平均误差和排序一致性；
5. 使用项目现有 ONNX Runtime，禁止引入第二套生产推理运行时；
6. macOS Core ML 与 Windows DirectML 都在禁用默认 CPU 回退时完成完整图真实推理；
7. 记录节点 EP 分配、冷启动、热推理、内存、显存、包体和1000张任务吞吐；
8. 在训练/调参集之外的冻结盲测集验证误杀率、人工审核率和与人工星级差异；
9. 新证据只能通过智能选图独立 feature 接入，不修改上游 RapidRAW 业务实现；
10. 眼睛冻结回归必须零退化，任一新增模块不得突破眼睛硬门禁；
11. 全部门禁通过并获得明确批准后，才允许将权重加入 Tauri 生产资源。
